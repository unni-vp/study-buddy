Protocols

Protocols

A network protocol is an agreed set of rules for communication. Both ends must agree how data is formatted, addressed, sent and received.

ProtocolFull namePurpose
TCPTransmission Control ProtocolSets up reliable communication, divides data into packets and supports checking/reassembly
IPInternet ProtocolAddresses and routes packets between networks
HTTPHypertext Transfer ProtocolTransfers web pages and related web data
HTTPSHypertext Transfer Protocol SecureEncrypted, authenticated version of HTTP for more secure web communication
SMTPSimple Mail Transfer ProtocolSends email from a client to a server and between mail servers
IMAPInternet Message Access ProtocolAccesses and manages email kept on a mail server, synchronising folders and status

HTTP and HTTPS

FeatureHTTPHTTPS
UseTransfers web pages and related web data.Performs web communication using an encrypted connection.
Data in transitDoes not itself encrypt the connection.Protects transmitted data against being read by an interceptor.
AuthenticationDoes not itself authenticate the server through a certificate.Uses certificates to help authenticate the server connection.

Do not write that HTTPS makes a website completely safe. It protects data in transit and helps authenticate the connection; the site or user's device could still be harmful or compromised.

SMTP and IMAP

FeatureSMTPIMAP
Main jobSends email.Accesses and manages email stored on a server.
CommunicationClient to outgoing mail server, and between mail servers.An email client communicates with the server holding the mailbox.
Example actionSend a new message to somebody else.Read a message or synchronise folders and read/unread status across devices.
What to distinguishSending a message does not replace mailbox access.Reading or organising a mailbox is different from sending a message.

Following an email

  1. A sender's email application submits an outgoing message using SMTP.
  2. Mail servers use SMTP to pass the message towards the recipient's mail server.
  3. The recipient's application uses IMAP to access the stored mailbox and manage messages.
  4. Server-held folders and read/unread status can then be reflected on the recipient's other devices.

SMTP and IMAP are not alternative names for the same step. One handles sending; the other handles access to the mailbox.

Reliable delivery and addressing

IP identifies destinations and supports routing packets between networks. Different packets may travel by different routes. IP alone does not guarantee that all data arrives in order.

TCP manages reliable end-to-end communication. It supports sequencing, detects missing data and arranges retransmission where necessary, helping the receiver reconstruct the data correctly. A destination address answers “where?”, while reliable delivery answers “has the complete data arrived correctly?”.

An HTTPS connection protects web data while it travels and helps authenticate the server connection. That matters when submitting login or payment details. It does not prove that every claim on a website is truthful or that a downloaded file is harmless.

Missing and out-of-order data

Imagine a file is sent in three numbered parts. The receiver gets part 2, then part 1, while part 3 is missing.

ResponsibilityHow it helps in this example
IP addressing and routingDirects packets towards the destination, even when routes differ.
TCP reliabilityDetects the missing data so it can be sent again.
TCP orderingReconstructs the data in the intended order rather than arrival order.
EncryptionProtects the contents from being read by an interceptor. It solves a different problem from ordering.

Using TCP and IP does not itself encrypt the file. Reliable delivery, routing and confidentiality are separate jobs, even when a single application uses all three.

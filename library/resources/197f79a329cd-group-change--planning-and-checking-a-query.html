Changing data

Planning and checking a query

Before writing, identify the operation:

NeedCommandEffect on stored records
Retrieve informationSELECTNo stored records change; results are returned.
Add a recordINSERT INTO … VALUESCreates a new record with the supplied values.
Change valuesUPDATE … SETEdits fields in matching existing records. Without WHERE, all records are affected.
Remove recordsDELETE FROMRemoves whole matching rows. Without WHERE, all rows are removed; the table remains.

Then check:

  1. Fields: which columns must be displayed or changed?
  2. Tables: where is the information stored?
  3. Conditions: which rows should qualify? For two tables, what key values must match?
  4. Order: is a particular sort required?
  5. Accuracy: are names, operators, quotes and values correct?

Trace the query against a few records. A correct-looking query can still answer the wrong question if its filter or linking condition is wrong.

Find the meaning of the mistake

A query can use valid SQL while selecting the wrong data. Check its meaning against the task before changing punctuation at random.

Intended taskPossible mistakeWhy it changes the answer
Retrieve pupils in year 10 or year 11.YearGroup = 10 AND YearGroup = 11One record cannot have both values in the same field. Use OR for these alternatives.
Show the shortest loans first.ORDER BY DaysLoaned DESCDESC puts the largest value first. Use ASC for the smallest first.
Show each pupil beside their own loans.The query names both tables but omits the key-matching condition.Unrelated pupil and loan rows can be paired together.
Change one pupil's year group.UPDATE has no WHERE condition.Every record in the named table is changed, rather than just the intended pupil.
Remove a returned loan, keeping the other loans.DELETE has no WHERE condition.Every loan record is removed, although the table structure remains.

To check a filter, take one record that should qualify and one that should not. Evaluate every condition for both. To check a two-table query, follow one primary-key value to its matching foreign-key values before predicting the result.
